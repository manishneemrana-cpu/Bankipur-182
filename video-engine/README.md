# Auto Real-Estate Video Engine

Submit a project's basic data → get a luxury marketing reel (aerial map flyby + cinematic building shot +
animated text + voiceover + music) in **9:16** and **16:9**.

```
apps/
  web-admin/        Next.js admin panel (projects, new-project form + map picker, job progress, preview/download, settings)
  worker/           Express API + BullMQ workers (the 4 pipeline stages) + adapters
packages/
  shared-types/     zod schemas + TS types shared by API, worker, web and the Remotion template
  video-template/   Remotion composition (intro → map → cinematic → outro, synced captions, ducked music)
supabase/migrations/0001_init.sql   accounts, brand_kits, projects, jobs, notifications (+ RLS, storage bucket)
```

> This lives in `video-engine/` and is independent of the Next.js app at the repo root.

## Pipeline

Each stage is a BullMQ job (one queue per stage). A BullMQ **flow** runs stages 1-3 in parallel and `render` only
after all three succeed. Stage state is mirrored to the `jobs` table so the UI can show progress.

| # | Stage (queue)  | What it does | Adapter / env var |
|---|----------------|--------------|-------------------|
| 1 | `voiceover`    | custom script *or* template-generated script → TTS → stored audio + exact duration → sentence timestamps | `VoiceoverProvider` · `TTS_PROVIDER` (elevenlabs / google / azure / mock) |
| 2 | `map`          | Puppeteer steps a Mapbox-style flyby frame-by-frame (route line + pulsing pin + label) → ffmpeg → MP4 | `MapProvider` · `MAP_PROVIDER` (mapbox / google / cesium / mock) |
| 3 | `cinematic`    | elevation image → image-to-video clip. **No elevation image → skipped; render applies a local Ken Burns pan/zoom** (free) | `ImageToVideoProvider` · `VIDEO_PROVIDER` (luma / runway / kling / mock) |
| 4+5 | `render`     | Remotion server render of both aspect ratios + thumbnail → upload → mark done → notify | — |

Provider choice is read from the env var as a default and can be overridden per account in **Settings** (dropdown per stage);
the choice is snapshotted onto each project when it's submitted.

### Script templates (`apps/worker/src/script/templates.ts`)
Four templates keyed by project type — `plot-investment`, `tower-skyline` (tower + commercial), `villa-lifestyle`,
`home-family` (2/3 BHK) — each in English, Hindi (Devanagari) and Hinglish. Each slot has several wording variants; one is
chosen per project with a seeded pick (stable per project, varied across projects). Templates never invent facts
(no RERA numbers, prices, returns, possession dates): paste a custom script for anything factual.

### Video template (`packages/video-template`)
`logo intro 1.5s → [map flyby 60% | cinematic 40%] with sentence-synced captions over the voiceover → outro (logo, contact, CTA)`.
Music auto-ducks under the voiceover. Props are typed (`VideoProps` in shared-types). Run `npm run studio -w @ave/video-template` to iterate visually.

Bundled assets: three **original** ambient loops generated by `npm run assets` (no third-party audio, so no licensing
questions) and Playfair Display / Inter / Noto Sans Devanagari (SIL OFL).

## ⚠️ Paid APIs are OFF by default

As requested, paid calls are implemented one provider at a time after you confirm a key. **Live now: ElevenLabs TTS** (`providers/voiceover/elevenlabs.ts`, verified only against a stubbed `fetch` — not yet against the real API). Everything else is still stubbed: Each remaining real provider call is a clearly marked
`TODO(paid-api)` block (with the endpoint, headers, body and polling flow written out in the comment) and, while
`PAID_APIS_ENABLED=false`, each adapter returns a **mock** result (synthetic voiceover, procedural map, local push-in clip) so the whole
pipeline works end to end for free. If you set `PAID_APIS_ENABLED=true` + a key before the TODO is implemented, the stage fails with an
explicit `PaidApiNotImplemented` error rather than silently mocking.

TODO stubs to enable one at a time, once you confirm each key is ready:

## Quick start (no keys, no Supabase needed)

```bash
cd video-engine
npm install
docker compose up -d redis            # or: redis-server
cp .env.example .env
npm run dev:api                       # http://localhost:4100  (serves files too in local mode)
npm run dev:worker                    # separate terminal
npm run dev:web                       # http://localhost:3100
```
Local mode stores data in `.local-data/` (JSON file + disk) — **dev only**. Remotion fetches clips over HTTP, so keep the API running while rendering.

Useful scripts (all in `apps/worker`):
- `npm run demo`  — renders both aspect ratios from placeholder clips + mock voiceover (no Redis/API) → `.local-data/demo/`
- `npm run smoke` — submits a project to a running API/worker and polls it to completion
- `npm test`      — script-template, timing and timeline unit tests

## Production setup

1. **Supabase**: create a project, run `supabase/migrations/0001_init.sql` (tables, RLS, public-read `video-engine` bucket).
   Set `SUPABASE_URL` + `SUPABASE_SERVICE_KEY` (server only). Setting them switches both DB and storage to Supabase.
2. **Auth**: set `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` in the web app → `/login` appears and the API requires a valid
   user JWT; each user gets their own account (brand kit, settings, projects). Without them everything runs as one dev account.
3. **Redis**: any Redis ≥ 6.2 (`REDIS_URL`). Use a persistent instance.
4. **Run**: `docker compose up --build` (images install Chromium libs + Noto fonts). Scale `worker` replicas for throughput;
   keep `RENDER_CONCURRENCY × replicas` within CPU. Renders are CPU-bound — give workers ≥ 4 vCPU.

## Notes & known limits
- **Map flyby is frame-stepped** (`jumpTo` per frame, then wait for idle) rather than real-time `flyTo()`. Same easing and look, but deterministic: no dropped frames on a slow box.
- The route line is an illustrative arc into the project, not a real driving route. Swap in a Directions API polyline in `providers/map/page.ts` if you want one.
- Map + cinematic clips are captured **square** so one asset center-crops cleanly to both 9:16 and 16:9.
- Sentence timings are estimated proportionally from audio length. With ElevenLabs the timings are exact (`/with-timestamps` character alignment); other providers, or a text-normalised alignment, fall back to the estimate.
- Provider-hosted video URLs expire; the stage must download and re-upload (noted in each TODO).
- The map picker uses Leaflet + OpenStreetMap tiles and Nominatim search (free, no key; light, user-initiated use only per their policy). Swap for Mapbox GL in `MapPickerInner.tsx` if you prefer.
- Mapbox ToS requires its logo/attribution to remain visible in captured output — keep that in mind when implementing the live Mapbox backend.
- CPU render speed here was ~2 min per reel for a 30s video on 4 vCPUs.
